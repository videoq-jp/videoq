# API traffic metadata control

`cutover-api-traffic.cjs` changes only `MIGRATION_TRAFFIC_STATE` for the fixed production API, or an explicitly named isolated fixture. Preparation records the original absent/running flag, current deployed version and hashes of the other binding/configuration metadata. It stores no secret value or ordinary variable value. Already paused or ambiguous configurations are rejected.

The adapter requires an ownership callback before and after mutations. Restoration additionally requires a verified-backend handoff callback; both defaults reject mutation. The full coordinator must persist the original plan under its owned hold, freeze deployment automation, verify that the deployed application implements the pause middleware, and bind restoration to the completed recovery/cutover handoff. No production CLI, automatic caller, token grant or capability activation is introduced here.

The Cloudflare transport is restricted to fixed HTTPS Worker metadata endpoints, GET and multipart settings PATCH, no redirects, bounded responses and sanitized API failures. Every other binding is inherited by name. Secret values are neither retrieved nor re-sent. Existing message/tag annotations are retained. All other settings and binding descriptors must match their original hashes on readback. The initial pause refuses a changed code version.

Inheritance defaults to the latest uploaded version. The adapter therefore requires a single 100% deployed version that also matches the latest version inventory. Split deployments and unpublished versions are rejected. Cloudflare's deployment/version metadata can temporarily disagree after a settings update: the adapter performs at most 20 read-only observations, waiting one second between them, and then fails closed. This settling loop never re-sends PATCH. Ownership is checked again before a later mutation. These are observations, not an atomic compare-and-swap against a separate administrator's deployment; automation exclusion and the operator trust boundary remain required.

An accepted update whose response was lost is reconciled from settings readback. Repeating a completed pause does not create another update. Restoration returns the original absent/running flag, preserving the same backend bindings. A different-backend handoff requires the later explicit coordinator path. Runtime/backend metadata drift is refused rather than silently overwritten.

`trafficPaused` describes the metadata flag. It is not proof that the application rejects requests or that in-flight work, Lambdas, external effects or database writers have drained. The production coordinator must separately check actual paused responses, readiness and the remaining fences. The returned receipt explicitly leaves `inFlightDrainProven=false`.

References: [Cloudflare settings PATCH and multipart form](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/script_and_version_settings/methods/edit/), [binding inheritance semantics](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/script_and_version_settings/), [deployment inventory](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/deployments/methods/list/).

## Owned pause and abort composition

`cutover-owned-api-traffic.cjs` binds the production plan to the same DynamoDB run/global owner. Its capability defaults to disabled; a deployment-freeze verifier is mandatory. It requires the exact execution-definition hash, a running execution, matching source/owner, no DB mutation, and deployment admission still marked stopped. Before the first settings update it atomically stores the immutable original plan/hash, increments the revision, and records API restoration and verified-pause markers as false.

The default production response verifier sends anonymous, non-redirected, no-store GETs to the fixed `https://videoq.jp` endpoints. Liveness must remain 200. For pause, both readiness and the pre-auth session endpoint must return the actual `MIGRATION_PAUSED` 503 body, Retry-After 60 and Cache-Control no-store. The verified-pause marker is recorded only after these checks. The broker and consumer parent both refuse moving into consumer pause when an owned API plan lacks that proof, avoiding a stuck intermediate command or a metadata-only assertion of quiescence.

Pre-write abort restores the original backend/traffic under a mandatory handoff callback and verifies actual DB readiness before recording completion. It may run while consumers remain paused; consumers resume afterward, and deployment automation restores last. A changed backend, started DB mutation or terminal execution requires the later full recovery/handoff path. This component does not enable a post-write D1 rollback by resetting a boolean.

Ordinary hold release, terminal generic recovery and the final atomic state-machine release all refuse unfinished API restoration. Deployment automation restoration also refuses it. Lost intent/completion responses reconcile exact readback, duplicate commands do not replace the original plan, and a completed plan cannot pause a second time. The callable components are in the operator bundle and its CI/CD selectors. No production command, new token, automatic AWS caller or capability activation was introduced.

The combined path—deployment freeze → API pause/proof → consumer preparation/pause → API restoration → consumer restoration → deployment restoration → hold release—passed with actual DynamoDB Local transactions. SFN/GitHub/Cloudflare transports and response callbacks were mocked there. Separately, the production response verifier passed against the actual Hono pause middleware without DB credentials (8 Hono tests), and its read-only ready probe passed against production. All 442 Node tests, 30 DynamoDB integrations, 57 infra tests, API typecheck/lint and AWS definition validation passed. The packaged component loads without application dependencies and the broker's pin matches its packaged definition. [Owned API evidence](evidence/cutover-owned-api-traffic-2026-11-16.json).

This composes the pre-write stop/abort path; it does not complete production orchestration, AWS in-flight/build drain, final data movement, inverse recovery, a changed-backend handoff, search/performance/budget acceptance or final candidate E2E. Production remained PostgreSQL with no D1 binding or cutover selectors after main `498b1c89` CD; health/ready were 200 and all three workers Active/Successful.
