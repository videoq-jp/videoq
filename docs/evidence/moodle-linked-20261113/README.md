プレビュー用のAPI応答やメディアスタブを使わず、インストール済みのMoodle
5.1.8+ / 標準Boostテーマと、作業ツリーのVideoQ API・Web・プラグインを接続した。
管理者・先生・生徒・副担当には専用のテストアカウントを使用。
本番へのデプロイ・公開は行っていない。

## 検証中に修正した点

- Moodleが署名した質問者の氏名・メールアドレスをセッションに保持し、回答保存と
  同時に質問者情報を記録。講座所有者の既存履歴・CSVと、本人のPrivacy API出力に反映。
  ブラウザの入力から質問者・講座所有者・権限を選ばせない。
- Moodleの履歴内の参照にも、通常のチャットと同じSRT時刻解析・動画選択処理を使用。
- 管理者向けの接続完了案内を、旧動画取り込み方式から先生ごとの既存講座連携に変更。
- AI側の画像にMoodle標準のデフォルトアバターを使用。
- `/teaching/connect` を既知の非公開認証ページとして登録し、404タイトルや
  未ログイン時の不適切な扱いを防止。

Moodleプラグインは **0.25.3 / 2026111304** に更新。
両プラグインのCLIアップグレードとZIP生成を確認した。

## 回帰チェック

PostgreSQLのテストは専用の一時データベースを作成・削除して実行。

- 連携・講座履歴ビュー：12件通過。
- 質問者情報の保存・CSV、ネイティブ認証・セッション：35件通過。
- Moodle署名からの質問者情報を加えた教師接続テスト：8件通過。
- 本人のPrivacy API出力・削除：8件通過。
- WebのURL判定・認証・講座接続画面：27件通過。
- API型チェック、lint、Nodeビルド、Webビルド：通過。
- Moodle PHP署名契約、パッケージ契約、0.25.3 ZIP生成：通過。

初回のPrivacy APIテストは並行負荷下で10秒のフック制限に達したため、
フックとテストの制限を60秒にして単独で再実行し、8件すべて通過。
実環境の再生権限確認でも一度403となり、再実行で成功した。
高負荷時の応答時間や安定性を保証する検証ではない。

## 環境と範囲

専用Composeプロジェクト `videoq-linked-20261113` を使用し、Moodleデータと
PostgreSQLを既存ラボから分離。S3の実体とローカルの実モデルは既存ラボを利用。
事前に実処理された公開テスト動画と、その実字幕・実ベクトルを複製して
ネイティブ講座の検証教材に設定した。今回、新規アップロード・ASR・索引作成を
再実行したという証拠にはならない。AI応答・Moodle通信・動画配信は代用品ではない。

モバイル確認はego-browserの390pxエミュレーション。iPhone実機や別テーマ、
本番負荷、Google Classroom実環境はこの検証に含まない。
Moodleの日本語コア言語パックは未導入のため、標準UIは英語表示。

作業ツリーの主要ファイルのSHA-256と検証結果は [result.json](result.json) に保存。
認証情報・Cookie・接続チケット・秘密鍵・実行環境ファイルは含めていない。
