# バックエンドのドメインモデル

VideoQは、業務の意味と整合性を中心に境界を設計する。クラスの数やフォルダ名をDDDの達成基準にしない。ドメインの判断はデータと純粋な関数で表し、ユースケースはその実行順序と外部能力を組み合わせる。

## コンテキストと用語

`apps/api/src/domain/<context>` がサーバー固有のルールの所有先。`packages/domain` はブラウザー・API間の shared kernel（共通の意味を維持する小さなモデル・ルール）。共有する必要のないサーバーのルールは追加しない。

| コンテキスト | 所有する意味・ルール | アプリケーション側の主な入口 |
| --- | --- | --- |
| learning | 講座、教材の所属・並び順、ネイティブ参加、受講者招待と配送状態 | courses、membership、course-memberships |
| media | 動画、アップロード容量、教材の変更、文字起こし状態、視覚処理の版 | videos、media、worker-internal |
| conversation | 回答、回答生成条件、会話の存続 | chat |
| search | シーン、字幕分割、索引対象の版 | evidence、maintenanceの索引処理 |
| qa | 質問・返信・投票、本人の変更とモデレーション、元教材と現在の動画の可視性 | qa |
| billing | プラン、利用枠、容量・月次アップロード枠、課金による権利の更新 | billing、利用枠を予約する各ユースケース |
| identity | ユーザー名、管理者権限、OAuth同意 | account、admin、認証アダプター |
| lms | LMSによる管理権限、登録、連携、ネイティブ学習許可、リソース世代 | lms、lti |
| skills | 教材由来のスキル、出典保証、生成状態と監査 | skills |
| operations | ジョブ、失敗・再試行、外部タスク、保守期限、アカウント削除 | tasks、maintenance、バックグラウンド実行 |

「講座」は教材をまとめ参加の境界になるもの。「教材の所属」は講座と動画の関連。「受講者」は講座に参加するユーザーであり、両者をコード上の `membership` という語だけで同一視しない。「学習許可」は現在の権限・教材範囲から導出するもので、ログイン済みというだけでは成立しない。「リソース世代」は同じ外部IDを再利用した古い処理から現在の教材を保護するための世代。

## コンテキスト間の関係

ドメイン層内で公開する上流ルールは以下に限定する。`domain-contexts.test.ts` が実際の依存を検査する。

- identity → billing/signup-quota: アカウント作成時の初期利用枠。課金プロバイダーの型は持ち込まない。
- conversation → lms/subject-identity: 外部学習者の正規化されたidentityを会話の永続識別に使用する。セッション証明はapplicationで検証する。
- lms → billing/quota-policy: 教材アップロード予約の失敗を、容量・月次利用枠の優先順位で判断する。
- qa → learning/native-course-access: ネイティブ講座の参加・閲覧条件を共有する。Q&A固有の投稿や削除条件はqaが所有する。
- 全コンテキスト → shared kernel: 共有された字幕・回答・タグ・プランなどの意味。

その他の連携はapplicationのユースケースや注入された能力で行う。ドメイン層が別コンテキストのリポジトリやintegrationを呼ばない。LMSから受けたプロトコルのclaim、Stripeイベント、AI SDKの結果は外側で内部モデルへ変換する（anti-corruption layer）。外部の型をそのまま業務モデルにしない。

## 集約と整合性の境界

集約は「必ず一緒に整合性を保つ更新」の単位。巨大な講座オブジェクトへ動画・受講者・会話をすべてロードしない。各コマンドに必要な最新の事実をロックまたは条件付きSQLで評価する。

| 単位 | 同一コミットで守る不変条件 |
| --- | --- |
| 招待の受諾 | 現在の講座権限、招待状態・期限・宛先確認、招待の受諾と受講者追加。本人の受諾再試行だけ冪等に成功する |
| 招待の作成・再送 | 招待・トークンの更新と配送意図の保存。実際のメール送信はコミット後 |
| 講座の教材所属 | 所有・LMS管理条件、重複、並び順、実際に挿入した件数 |
| Q&A変更 | 現在のセッション・教材範囲、投稿者または管理権限、質問・返信の更新と監査記録 |
| アップロード・動画削除 | 現在の版・処理状態、容量枠、予約・確定・返却、必要な後続タスク |
| 利用枠 | 使用量と予約の比較を更新時に行う。返却は予約した期間・版に対応する |
| 会話の確定 | 会話の現状態と回答保存、履歴への一度だけの記録 |
| 課金反映 | イベント重複排除、古いイベントとの調停、管理者指定枠を上書きしない権利更新 |

`learning/invitation-lifecycle.ts` は招待をIDを持つエンティティとして表し、そのスナップショットから受諾・辞退を判断する。PostgreSQLはロックした実体を渡し、D1は同じ判断代数を原子的なSQL条件に変換する。ユースケースで先に読み取ってから無条件に保存する方式へ変更しない。

ドメインの決定と配送イベントは区別する。後続の索引・削除・メール配送は永続outboxの既存タスクで伝達する。同期中のイベントバスでDB更新前に外部処理を起動しない。別集約・外部サービスをまたぐ失敗は冪等な再試行で収束させる。

## 配置の判断

- **domain**: 「誰が変更できるか」「どの状態から遷移するか」「どの枠を適用するか」。時刻・現在状態を引数で受け取り、HTTP、DB、SDK、環境変数を知らない。
- **application / featuresのユースケース**: 認証済みコマンド、権限証明、入出力モデル、予約→生成→保存の順序、ポート。運用設定の解決やDTOは自動的にドメインモデルとはみなさない。
- **integrations / persistence / transports**: 実装の組み立て、SQL・ロック、外部型の変換、HTTPエラー、外部タスク配送。

既存features内の複合的な権限チェックは、アプリケーションの証明やポートも扱うためユースケース側に置く。純粋な判断を新たに抽出するときは上表の所有コンテキストへ置く。旧`application`名の互換exportを増やして所有先を曖昧にしない。

Pythonのmedia workerは同じ教材処理コンテキストの別実行環境であり、独立した別の業務概念ではない。`worker_python/domain` がジョブ・字幕・シーン・処理状態、`use_cases` が文字起こし・視覚公開の手順を所有する。通信のジョブ形式は契約・fixtureで維持し、Pythonから検索索引の内部実装を呼ばない。

## 検証

APIの型検査ではdomain全体もDOMなしでコンパイルする。ESLintでdomainからapplication・framework・永続化への依存を禁止する。アーキテクチャテストは実ファイルの推移的依存とコンテキスト間の公開先を検査する。業務テストとD1/PostgreSQLの永続化テストで、期限境界、再試行、並行更新、権限変更時の不変条件を検証する。

## 業務ルールの所有先の追加整理

業務ルールは以下のファイルを正とする。D1、PostgreSQL、API入力検証は同じ判断を参照する。

| 所有先 | 判断 |
| --- | --- |
| learning/course-report | 集計日・期間の妥当性、教材とログの集計対象条件 |
| learning/tag-policy・course-tags | タグ名・色、表示範囲、管理可能な教材、上限、変更版の一致 |
| lms/resource-mutation | 共有教材の削除禁止、未完了アップロードの返却、教材の内容・講座名の保持 |
| lms/materials-snapshot-policy | 同期スナップショットの重複・講座範囲・件数 |
| lms/privacy・privacy-policy | 個人データの範囲、匿名化・消去計画、ページ継続条件 |
| media/content-read・material-management・material-mutation | 内容のサイズ上限、編集可能な状態、版・参照の整合性、更新と再処理の計画 |
| conversation/citation-policy | 引用元IDと本文内の安全な引用位置 |
| operations/retention-policy | 履歴保持期間・一度に処理する件数 |
| skills/model・policy・batches | 生成状態、出典との一致、知識の欠落・重複、全主張の監査、処理分割 |

skillsを独立したコンテキストに追加した。教材本文を入力として受け、生成状態と出典保証を所有する。永続化ポートがドメインの状態型を参照し、逆方向には依存しない。

`application/material-mutation`、`features/course-tags/policy`、`features/skills/core` に残る呼び出し口は、ドメインの違反を既存のApplicationErrorへ変換する。判定条件のコピーは持たない。タグの非同期判定もこの境界で変換する。セッション証明の検証、DTOの組み立て、Markdownの出力、DBの原子的更新は各外側の責務として残す。

`domain-policy-ownership.test.ts` は期間の閾値、画面に提示する操作と状態遷移の整合性、同期・非同期のエラー変換を検証する。`domain-contexts.test.ts` と `architecture-boundaries.test.ts` は新しい所有先も含む全ドメインファイルの依存を検証する。

## 追加監査の所有先と回帰防止

issue #1703〜#1729の正本・呼び出し元・契約試験は `domain-rule-ownership.json` に記録する。APIとPythonのテストは、正本の一意性と実ファイルの依存経路を検証する。意味が同じかは入口/DB/言語間の契約試験でも検証する。任意に名前を変えた業務ルールのコピーを自動的にすべて見抜けるわけではなく、変更レビューではこの対応表も更新する。

講座名と動画タイトルはtrim後に255 UTF-16単位を上限とする。既存の保存値は一括変更しない。新規作成・明示的な名前更新に適用する。単一PUTとmultipartの物理的な上限差は維持する。

AI枠の消費根拠は `billing/ai-consumption` に明示する。完成した回答、確定後の失敗、文章を一部生成したstream、provider呼び出しが完了した外部処理の違いを保持し、一律に課金タイミングを変更しない。

スキル生成は `skills/lifecycle` が次の操作・再生成上限・全memberの監査・公開を決める。外部AIの呼び出し・キャンセル・lease・保存はユースケース側に残す。LMSの提供機能と操作権限、教材の世代・所有者・接続の不変条件もそれぞれドメインの正本から判断する。

検索分割はdomainの同期generatorが必要なデータを要求し、applicationがembedding/境界の外部処理を実行して結果を返す。Otsuの数値計算もdomainにあり、バッチ取得とdurable checkpointの保存はapplicationが担当する。再索引のdomainはmessageを生成し、保存→配送はapplicationで行う。既存のメモリ上限・逐次加算順序・outbox・CASは維持する。

Pythonの字幕選択・視覚分割・文字起こし状態の判断は `worker_python/domain` が所有する。ジョブclaimの状態表はTSとPythonが同じJSON fixtureを読み、DBの原子的claim/lease更新を保つ。
