# 検索と映像確認のMCP設計

VideoQの検索・字幕取得・映像確認・講座情報は、エージェントから独立したツールとして定義する。内部の回答生成もMCPで一覧を取得して実行し、外部のHTTP MCPと同じ処理を使う。

## 責務と接続

`apps/api/src/tools/` は入力検証、閲覧範囲の制約、検索・映像確認、実行スコープの上限を担当する。LangChainやLangGraph、回答の引用番号、会話履歴には依存しない。この依存方向をESLintで検査する。

`integrations/evidence-mcp.ts` は内部接続の組み立てを担当する。回答ごとにMCPサーバーとクライアントを作り、`InMemoryTransport` で接続する。HTTP通信や所有者のAPIキーは使わない。完了・失敗・中断時に接続と検索リソースを解放する。検索接続は最初の検索まで開かない。

`lib/rag-mcp-tools.ts` は接続済みMCPクライアントからツールを取得してLangChain形式に変換する。ツール本体や接続方式は知らない。返された根拠に回答内の `sourceId` を付け、進捗をUIへ渡す。引用の継続性と会話履歴は既存のエージェント側で管理する。

外部公開は既存の `/api/mcp` を使う。`features/mcp/evidence-tools.ts` が認証主体から講座へのアクセスを確認し、同じツール定義を実行する。外部の呼び出しには `course_id` が必要で、`ownerUserId` や許可動画一覧を引数として受け取らない。

## 公開ツールと結果

検索は `search_scenes`、字幕は `read_video_window`、映像確認は `overview_video`、`skim_video`、`inspect_clip`、`focus_clip`、講座情報は `get_course_info` を使う。画像確認が無効な環境では `inspect_clip` と `focus_clip` を公開しない。

成功時の `structuredContent` は `{ result: ... }`。根拠には動画ID・タイトル・時刻・本文・必要に応じて根拠種別を含む。MCP側では回答の引用番号を付けず、ストレージキーや所有者IDも返さない。検索結果がないこと、画像が使えないこと、利用上限などは通常の結果として明示する。

基盤の障害は `isError: true` と `error.code` で区別する。`CONFIGURATION_ERROR` は設定不備、`EXECUTION_FAILED` はその他の実行障害。SQLやプロバイダーの例外詳細は送らない。内部アダプターはこれらを例外に戻し、根拠がない通常回答として処理を続けない。スキーマ不備はモデルが修正できる結果として扱う。

内部接続では検索の開始と完了をMCPのprogress通知で送り、アダプターが通知の形を検証してからUIへ渡す。キャンセルはクライアントのsignalからMCPハンドラーと上流処理へ伝達する。外部HTTPは既存のJSON応答モードのため途中のprogress通知を配信せず、完了結果を返す。HTTPの切断signalは処理へ渡すが、ステートレスな別HTTPリクエストからのキャンセル追跡は行わない。

## 権限と利用制限

内部ではチャットのセットアップで確認済みの所有者・講座・許可動画を固定する。共有リンクやLTIのために、所有者全体の権限へ広げない。講座情報の動画一覧と件数も、許可動画で絞ってからページングする。PostgreSQLとD1の両方で同じ契約を使う。

検索3回、画像確認合計4回・48枚などの既存上限は、内部では回答ごとの実行スコープで共有する。外部HTTPはステートレスなので、スコープのカウンターだけを継続的な制限として扱わない。

外部には既存のユーザー単位の読み取り上限に加え、1時間240単位の根拠取得上限を適用する。検索は1単位、画像確認は要求枚数の最大値で8または16単位を実行前に予約する。このカウンターは既存のレート制限基盤を使い、別リクエストや別クライアントでも共有する。

外部の検索・画像確認は講座所有者の既存AI利用枠を1呼び出しにつき1枠予約する。プロバイダー処理が一つも完了しなかった呼び出しは枠を返す。字幕・講座メタ情報だけの取得はAI枠を消費しない。内部は回答側が予約済みの枠と利用量記録を共有し、MCP経由にしたことで二重に予約しない。

## 検証

`test/mcp-evidence.test.ts` はLangGraphを使わない実MCPクライアントで、一覧・構造化結果・権限・入力検証・継続的な制限・AI枠・進捗・キャンセル・障害の秘匿を検証する。既存のRAG、映像確認、会話履歴、HTTP MCPのテストは、変更後の経路を検証する。

`test/workers/rag-agent.test.ts`、`rag-visual.test.ts`、`conversation.test.ts` はworkerd上で内部MCP経由の回答生成を検証する。講座リポジトリの共通契約は、許可動画による件数とページングの絞り込みを検証する。
