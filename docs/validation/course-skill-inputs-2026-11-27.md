# 講座Skills入力管理の検証

対象: Issue #1742。生成開始と入力管理の実装。LLM生成・公開・MCP配信は後続Issueで実装する。

## 実装

生成設定、入力照合の永続カーソル、固定入力を持つ生成ジョブをPostgreSQLとD1に追加した。所属変更と解析完了の通知で照合を促進し、60秒間隔の永続カーソルによる定期照合で通知欠落を回復する。PostgreSQLの外部ワーカーによる変更も定期照合で検出する。設定の既定値は生成・配信とも無効であり、生成設定用UIは後続Issueの対象とする。

講座構成の変更番号は、定期照合で観測した入力変更から進める。通知と構成番号更新の間にも、ジョブのclaim・checkpoint・completeは現在の所属ID、解析版、画像版、設定をDB内で再確認する。したがって、定期照合前に動画が除去されても旧ジョブは成果物を確定できない。設計資料のイベント送信予約を独立追加する代わりに、元データと永続照合カーソルを回復元にする。

PostgreSQLでは字幕のMD5を変更検出の識別子として使い、D1では既存字幕更新が同一バッチで更新するvideo_index_versionsを使う。MD5は内容の信頼性や外部ファイルの完全性を保証する用途ではない。旧動画でD1の識別子がない場合は上書きせず初期化する。所属の削除・再追加は新しい所属IDで区別する。

## 検証結果

- D1の実workerdと全migration適用済みDBで、登録先行・解析先行、重複通知、権限、通知欠落、除去と再追加、古いスナップショット、リース引き継ぎ、設定無効化の8ケースが成功。
- 専用のローカルPostgreSQL 17コンテナで同じ8ケースが成功。既存の開発用DBは変更していない。
- メンバー追加・保守処理・worker-internalの回帰34ケース、アーキテクチャ境界7ケースが成功。
- API型検査、API lint、PostgreSQLのmigration検査と生成元一致検査、D1 migration検査が成功。

生成の実モデル呼び出し、本番環境、公開と失効のMCP経路はこの段階の検証対象に含めない。対応する後続Issueで検証する。
