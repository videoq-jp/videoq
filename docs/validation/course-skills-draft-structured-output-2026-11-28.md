# 本文生成と自動修正の出力形式を制約する

講座51の905チャンクを抽出し、分類89ステップを保存した後、最初の本文生成が3回とも失敗した。保存応答は打ち切られていなかったが、適用条件 `useWhen` が上限12件を超えており、サーバー検査で拒否された。分類時の失敗2回と合わせて失敗上限5回に達し、ジョブは失敗状態で停止した。実候補は保存されていない。保存済み分類89ステップを追加推論なしで再生できることを確認した。

初回本文生成と回数制限付き修正にもJSON Schema出力を指定する。既存のWorkers AI文法互換化を使い、元のスキーマ・指示文・参照変換・サーバー検査は変えない。条件を12件で切り落とす処理や、検査上限の緩和、JSONモードへの自動フォールバックは加えない。制約に収まることは、出典の条件が漏れなく保存されたことを保証しないため、既存の監査と所有者レビューが必要になる。

合成知識21件による実モデル試験を1回行い、文法の受理とサーバー検査の成功を確認した。適用条件は1件で上限以内だった。利用回数は986から987へ増え、上限1,000回とジョブ・キャッシュを維持した。これは形式制約の互換性検証であり、実講座の意味的な正確さを示す評価ではない。

追加テストは変更前に1件失敗・13件成功となり、変更後は関連8ファイル72テスト、APIの型検査3構成、変更ファイルのlintが成功した。13件の適用条件を元のサーバースキーマが拒否することも確認した。[証拠記録](evidence/course-skills-draft-structured-output-2026-11-28.json)にソースと検証のハッシュを保存した。

保存済み分類の全タスクをオフラインで数えると222件あり、現在の機械的な完全性条件を満たすものは30件、情報不足で保留になるものは192件だった。この計数では未保存の合成プレースホルダーを使い、モデルによる本文生成・意味評価・実候補保存は一切行っていない。新しい再構築では分類89回と、30件それぞれの生成・監査・最大2回の修正を見込むと、追加149〜269回になる。モデルの分類結果が変わる場合や通信失敗などは別であり、この件数で完了を保証しない。

失敗ジョブの履歴を残した新しい再構築と、検証用所有者の利用上限を1,000回から1,300回に増やす案を用意した。承認前に上限変更や再構築は実行しない。動画の既存抽出結果905チャンクは再利用でき、ジョブごとの上限1,000回は変更しない。修正後のリモートCI、実講座での再構築と独立LLM評価は未完了である。本番公開・デプロイ・マージは行っていない。
