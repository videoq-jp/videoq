# 初回草案の検査とローカル検証の待機を修正する

## 問題と変更

講座51のrev3は累計1,089/1,300回、ジョブ内102回で停止した。保存済み102ステップを追加推論なしで再生すると `SKILL_UNSUPPORTED_EXCEPTION` で停止した。初回草案の機械検査が修正ループの外にあり、保存済みの同じ不正草案を再生しても回復できなかった。

初回草案の既知の検査エラーを最大2回の修正へ渡す。検査に通る草案を別に保持し、不正な初回草案は公開候補の本文として保存しない。修正できなければ本文なし・理由付きで保留し、次のタスクへ進む。初回の検査理由と修正履歴を保存する。既存の有効な草案への意味監査と、修正失敗時に最後の有効な草案を保持する動作は維持する。

参照IDの変換時に拒否され、修正へ渡せる草案が得られない場合も、架空の参照を認めず本文なしで保留する。出典変更、予算・利用量記録の障害、未知の内部例外は草案不備として処理しない。モデル段階の保存キー・元のスキーマ・指示文は変更せず、保存済みの応答を再利用する。候補の生成処理版は `course-draft-v5-initial-validation-repair` として記録する。

ローカル検証ではqueuedジョブの `lease_until` を0へ戻していた。新しい検証スクリプトは実行リポジトリの `nextWakeup` を参照し、未到来なら `retry_wait` と期限を記録して終了する。ドライバーは最大30秒ずつ待ち、モデル呼び出し0回の待機を正常に扱う。予算を使った進行も待機期限もない継続は拒否し、全体の待機には6時間の上限を設ける。本番のリース・バックオフSQLは変更しない。

## 検証

変更前は新しい回帰テスト2件が失敗、既存13件が成功した。変更後は関連9ファイル68テスト、API型検査3構成、変更箇所lintが成功した。

- 不正な初回例外の修正、修正不能な草案の保留と別タスクの継続、タスクIDの変更拒否、架空参照の保留。
- 出典変更・利用上限・課金記録・未知の例外の伝播。
- D1実DBでtickあたりモデル要求1回以下、段階再生で同じモデル要求を繰り返さないこと、修正履歴・本文なし候補・正常候補の保存。
- 不正候補の公開拒否と公開0件。既存の管理・認可・実ランタイム検証で配信・失効の制約も確認。
- リポジトリの待機期限前は実行をclaimせず、モデル要求と待機期限を変えないこと。
- 正常中断・障害バックオフの期限、モデル要求0回の待機継続、進捗のない予算中断と終端状態の停止。

新しいローカルrunnerとdriverは構文検査に成功し、driverから共有待機ポリシーをNodeのネイティブTypeScript読み込みで使えることも確認した。旧スクリプトは変更せず、新版とハッシュ付き記録をprivateディレクトリに保存した。現時点の新版は旧ランタイムの固定条件を保持しているため、新コードによる実行は拒否する。再構築の判断後に現行コードの変更記録を固定して実行可能にする。実モデルによるバックオフや生成の再試験は行っていない。

実講座の保存済み102ステップを修正後のコードで再生すると、同じ検査エラーで止まらず、5件の知識を使う `skill_draft_revision` の未実行境界に達した。その要求はオフラインで遮断し、DBの前後一致、905チャンクの再検査とハッシュ一致を確認した。これは再生と修正経路の確認であり、実モデルによる修正成功・内容精度の評価ではない。

[証拠記録](evidence/course-skills-initial-validation-repair-2026-11-28.json)に変更ファイルと検証スクリプトのハッシュを保存した。変更前HEAD cb556866の通常CI・CodeQL解析は成功しているが、本変更のリモートCIは別に確認が必要。

## 再実行前の判断

利用回数1,089/1,300、残り211回。元の入力マニフェスト、失敗済みrev2・rev3、905チャンク、保存ステップ、過去の比較・AI評価は保持している。今回の追加推論、本番変更、公開、デプロイ、マージは0件。

現行計画89段階をオフラインで再生すると224タスクのうち29件が機械的に草案生成可能で、195件は知識不足で保留となる。これは合成プレースホルダーを使う計数で、実草案や意味評価を生成・保存していない。

停止済みジョブを直接queuedへ戻す、失敗回数をリセットする、旧ステップのジョブIDを付け替える方法は採用しない。通常の所有者向け再構築APIでrev4を作る場合、905チャンクは再利用できるが、計画89回は再実行が必要。草案と監査を含め147〜263回が目安であり、分類の変更や障害は含まない。残り211回では完了を保証できない。

承認済みなのは前回のrev3再構築であり、rev4の作成は別の判断として提示する。提案は「累計上限1,300回を維持し、失敗履歴を残してrev4を通常再構築し、上限で停止する」。追加の利用上限増額は提案・実行しない。承認後も元の独立AI評価計画を維持し、生成完了時だけ全候補を評価する。
