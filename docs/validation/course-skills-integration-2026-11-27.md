# 講座Skillsの統合検証と運用

対象: #1742〜#1747、PR #1752。実装は標準で生成・配信とも無効。講座所有者の明示的な設定と、候補ごとのレビュー・公開が必要。

## 動作

1. 既存の字幕と動画所属から固定入力を作る。講座登録と解析完了の到着順序に依存しない。
2. D1では更新通知で照合を促進する。PostgreSQLでは通常の動画書き込みを単一接続のまま保ち、永続カーソルによる60秒間隔の照合を使う。いずれも通知の欠落を定期照合で回復する。
3. 一回の保守実行で未キャッシュのモデル呼び出しは最大一回。字幕抽出結果と計画・合成・意味検査の結果を保存し、中断後に再利用する。モデル呼び出しは一生成につき最大1,000回、連続した一時失敗は最大5回。各呼び出しには既存AI利用枠を適用する。
4. 字幕の知識に画像が必要な場合、既存の画像キャッシュから関連時間帯の最大8枚を読む。フレーム抽出は行わない。字幕の抽出結果を再利用し、画像の解釈を次の実行へ引き継ぐ。許可した画像IDと時刻を保存する。画像データは知識キャッシュやSkillに保存しない。画像の欠落・不鮮明な内容は保留する。
5. タスクの判断基準・手順・検証を揃えて候補を作る。3〜5個への水増しはしない。既存のSkill IDを維持し、影響した候補だけ本文を再生成する。明示的な再生成はgeneration epochを変える。
6. 生成全体の完了後、所有者が本文と出典をレビューする。編集時は意味検査をやり直し、未保存の編集や古い入力の公開は拒否する。ファイル集合をステージングした後、一つのトランザクションで公開先を切り替える。
7. 講座から根拠動画を除くと、その時点以降の一覧・メタ情報・本文・参照資料の取得を拒否する。照合の到着を待たない。再追加は別の所属IDとして扱い、古いURIを復活させない。残った知識から再構成した候補をレビューして公開するか、所有者が公開終了する。取得済み内容の回収はできない。

配信切り替えだけでは生成入力・epochを変えない。生成設定、ポリシー、言語の変更、明示的な再生成は入力を更新する。依存しない動画の追加は、公開済みSkillの取得を停止しない。

## 実施した検証

- PostgreSQL 17とD1 workerdで共通契約各18件。登録順序、重複、通知欠落、字幕ページ、所有者分離、リース奪取、古い入力の拒否、候補編集CAS、承認と公開の競合、不変ファイル、直接URI、配信切り替え、モデル処理再開を含む。
- 両DBで、解析済み動画→字幕抽出→固定応答モデルによるタスク生成→レビュー→公開→MCPサービス取得→除去→取得拒否→再追加の連続試験。実際の外部モデルへの呼び出しではない。
- 字幕・画像の知識抽出、タスク合成、実行制御の20件。画像IDの捏造、引用の捏造、画像バイトの永続化、画像版変更時の再解釈、呼び出し上限、壊れたチェックポイントを検査。
- 管理権限とtRPC公開面の8件。未認証利用と非所有者の設定・公開・取り下げ等を拒否。
- MCP固有の7件と既存MCPの回帰試験。新プロトコルの検証、明示的なSkills拡張への参加、旧SDK経由のツール呼び出しを確認。
- Web既存単体試験: 131ファイル・1,554件成功。追加した管理画面の11件では、編集の保存必須、公開後のロック、配信設定、動画除去、競合、出典再生、生成途中の操作禁止を確認。
- ego-browserで管理画面の表示、編集後の保存・公開、公開後の編集停止、除去時の停止表示、取得エラー、日本語/英語・390px幅を確認。固定データのStorybookであり、本番環境への接続試験ではない。
- API/Webの型検査とlint、PostgreSQL/D1 migration整合性・来歴検査。追加migrationは生成ツールで作成。

最終の機能受入試験は10ファイル・78件成功。実行ファクトリーから管理サービス・配信までのD1連続試験と、モデル境界の利用枠・予約返却・不正出力・画像入力・Workers AI互換性の7件を含む。Worker専用の16ファイル・118件も成功。ローカル全API試験は3,803件成功し、既存のworkerd重負荷試験2件が時間制限で失敗した。失敗した2ファイルを並列度1で再実行し14件すべて成功した。テスト時間の制限値は変更していない。CI結果はPRに記録する。PostgreSQLを使う既存テストにはQUOTA_TEST_DATABASE_URL、新機能の共通契約にはPERSISTENCE_TEST_DATABASE_URLを渡す。Pythonを使う既存テストには3.14が必要。

## 互換性と残る確認

既存のセッション型MCP SDKは2025-11-25を扱う。Skillsは2026-07-28のステートレスな拡張要求として同じ`/api/mcp`で受け付け、旧接続へ未対応の機能を広告しない。通常のtools/list、tools/callは既存の認可・制限を使うSDKへ橋渡しする。

特定のClaude/Codex製品がこの拡張を自動検出・選択するという保証はしていない。実際に使う対応クライアントの版を固定して、追加→生成→レビュー→公開→取得→除去→取得拒否を確認する必要がある。

既存Cloudflare認証を使った合成字幕の[実モデル生成試験](course-skills-live-model-pilot-2026-11-27.md)では、1件のSkill生成・意味検査・レビュー待ちまで確認した。実講座全般の品質・画像読解品質と、実装への効果比較は未実施。小規模な生成試験や固定応答モデルによる機能試験から効果改善を主張しない。下記の比較と実クライアント試験が完了するまで#1747と親Issueを完了扱いにしない。

## 効果比較の手順

同一講座から、再試行、適用条件の例外、図やコードが必要な操作、根拠が不足する質問を含む少なくとも10課題を選ぶ。正解と適用外の条件を人が先に記録する。各課題は同じコミット・未変更の作業ディレクトリから開始する。

| 条件 | 教材知識 | 検索ツール | Skill |
| --- | --- | --- | --- |
| A | なし | なし | なし |
| B | 検索結果 | 同じ動画検索 | なし |
| C | 検索結果 | Bと同じ | 同じ承認済み公開版 |

モデル、モデル版、プロンプト、推論設定、トークン・時間上限、実行ツールを固定する。Aは知識なし対照群のため検索を無効にする。BとCの差はSkillだけにする。課題と条件の順序を入れ替え、独立した状態で複数回実行する。

Codexではグローバルに登録済みのSkillも対照群への知識混入になり得る。[公式の無効化設定](https://learn.chatgpt.com/docs/build-skills)を使い、ユーザー設定ファイルを変更せず試行プロセスだけで無効化する。app-serverのskills/listによる事前確認では76件を発見し、発見した68種類の名前をskills.configで無効化し、bundled Skills・plugins・appsもそのプロセスで無効にした結果、有効0件・検出エラー0件となった。モデル呼び出しは0回。[事前確認の集計](evidence/course-skills-codex-evaluation-isolation-2026-11-27.json)は効果比較の結果ではない。各試行の実際の作業ディレクトリでも有効一覧を確認し、A/Bは0件、Cは選定した取得手順Skillだけとする。意図しないSkill・MCP接続・Web検索が有効なら、その試行を有効な比較結果に数えない。

課題ID、条件、試行、入力コミット、モデル、公開版、機能テスト結果、講座方針への適合、適用条件の誤判断、根拠なし断定、検証の充実度、所要時間、入出力トークン、モデル費用、検索/Skill取得回数をCSVへ記録する。Skill生成・意味検査の一回の費用と、利用時の費用を分ける。生成費用は再利用回数ごとの償却額も示す。価格表の版と不明な費用を明記する。

評価者には条件名を隠して採点する。機能成功率、誤適用率、根拠なし断定率、時間・費用の分布を条件別に比較し、失敗例も保存する。少数課題の改善を全講座へ一般化しない。結果と対応クライアントの版・実行ログを#1747へ添付する。

CIではAPI 5,385件が成功し、PostgreSQLの全migration照合2件で外部キー名の切り詰めによる差分を検出した。短い外部キー名をschemaへ明示し、生成した0075 migrationで改名した後、pgvector/pgvector:pg17の専用ローカルDBで空DB・既存データ入りDBの両試験が成功した。生成SQL・snapshot・journalは手編集していない。


講座51・Codex 0.160.0での[実講座・実クライアントの追加検証](course-skills-course51-codex-2026-11-27.md)では、1本の字幕から5候補（本文2件・根拠不足3件）まで確認した。CodexのSkills拡張未対応には、取得手順だけのローカルSkillと標準MCP読み取りツールを追加した。合成公開版での実Codex取得・失効確認と、実D1での既知URI拒否は別々に検証している。自動意味検査の偽陽性を発見し、根拠のない例外・適用外条件を禁止した。講座全体の品質と10課題の効果比較は未完了。
