# 講座Skillsの統合検証と運用

対象: #1742〜#1747、PR #1752。実装は標準で生成・配信とも無効。講座所有者の明示的な設定と、候補ごとのレビュー・公開が必要。

## 動作

1. 既存の字幕と動画所属から固定入力を作る。講座登録と解析完了の到着順序に依存しない。
2. D1では更新通知で照合を促進する。PostgreSQLでは通常の動画書き込みを単一接続のまま保ち、永続カーソルによる60秒間隔の照合を使う。いずれも通知の欠落を定期照合で回復する。
3. 一回の保守実行で未キャッシュのモデル呼び出しは最大一回。字幕抽出結果と計画・合成・意味検査の結果を保存し、中断後に再利用する。モデル呼び出しは一生成につき最大1,000回、連続した一時失敗は最大5回。各呼び出しには既存AI利用枠を適用する。
4. 字幕の知識に画像が必要な場合、既存の画像キャッシュから関連時間帯の最大8枚を読む。フレーム抽出は行わない。字幕の抽出結果を再利用し、画像の解釈を次の実行へ引き継ぐ。許可した画像IDと時刻を保存する。画像データは知識キャッシュやSkillに保存しない。画像の欠落・不鮮明な内容は保留する。
5. タスクの判断基準・手順・検証を揃えて候補を作る。3〜5個への水増しはしない。既存のSkill IDを維持し、影響した候補だけ本文を再生成する。明示的な再生成はgeneration epochを変える。
6. 生成全体の完了後、所有者が本文と出典をレビューする。編集時は意味検査をやり直し、未保存の編集や古い入力の公開は拒否する。ファイル集合をステージングした後、一つのトランザクションで公開先を切り替える。
7. 講座から根拠動画を除くと、その時点以降の一覧・メタ情報・本文・参照資料の取得を拒否する。照合の到着を待たない。再追加は別の所属IDとして扱い、古いURIを復活させない。残った知識から再構成した候補をレビューして公開するか、所有者が公開終了する。取得済み内容の回収はできない。

配信切り替えだけでは生成入力・epochを変えない。生成設定、ポリシー、言語の変更、明示的な再生成は入力を更新する。依存しない動画の追加は、公開済みSkillの取得を停止しない。
