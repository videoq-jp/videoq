# 講座Skillsの分類出力をJSON Schemaで制約する

講座51の全177本・905チャンクを抽出した後の分類で、モデルが既存タスクIDの制約に反する値や、配列であるべき `issues` に別の型を返した。これらをサーバー検査が拒否し、再試行が発生した。抽出済みの知識・保存済み分類ステップ・失敗回数・利用回数は保持した。

分類にもJSON Schemaによるモデル出力制約を指定する。最初の合成データによる実モデル試験は、Workers AIのXGrammarが文字列の正規表現と文字数制約を同時に扱えず失敗した。この失敗は保存し、JSONモードへの自動フォールバックは加えない。

送信する文法スキーマのコピーでは、正規表現を持つノードの `minLength` と `maxLength` だけを外す。元のZodスキーマと、モデルへの指示に含める全制約は変更しない。モデル応答は元のスキーマで再検査してから保存するため、長すぎる文字列・不正な形式・未登録のID・誤った型を許可する変更ではない。Workers AI以外への送信は変更しない。

修正後の実モデル試験は合成知識32件・既存ID60件で1回行い、文法の受理とサーバー検査の成功を確認した。2回の試験を通じてローカル所有者の利用回数は919から921へ増え、上限1,000回を維持した。試験前後のジョブ・分類ステップ・抽出キャッシュは同一だった。これは形式制約の互換性試験であり、講座の意味的な正確さや生成品質の改善を証明しない。

変更前に追加したテストは3件失敗・24件成功だった。修正後は関連8ファイル71テスト、APIの型検査3構成、変更ファイルのlintが成功した。長すぎる値と正規表現違反の両方を、使用量を保持したまま拒否することも確認した。[証拠記録](evidence/course-skills-planning-structured-output-2026-11-28.json)に試験とソースのハッシュを保存した。

講座51の再開前には、保存済みステップの再生と、元のスキーマ・プロンプト・入力が変わらないことを別途確認する必要がある。この変更についてのリモートCI、全講座の候補生成と独立LLM評価は未完了である。本番公開・デプロイ・マージは行っていない。
