# RTX 4090一枚で新しいモデル構成を使う

Gemma 4 26B A4B、EmbeddingGemma 2、Whisper large-v3-turboを、24GBのRTX 4090一枚で使うための配布設定です。
**Gemma 4のBF16重みを全てVRAMに載せず、最大40GiBをCPUメモリへオフロードします。**
ホストRAMは128GiBを用意してください。全GPU常駐の80GB GPU向け設定とは別のプロファイルです。

この構成はHelmの生成・設定契約を検証した候補です。Gemma 4の実機起動、三モデル同居時のVRAM、
画像読み取り、回答速度は未検証です。以前のGPT-OSS構成の実機記録を、この構成の合格証明として使わないでください。
CPU・GPU間の転送が回答速度に影響するため、公開前に下記の実機受け入れを行います。

## 必要な機器とファイル

| 項目 | 条件 |
|---|---|
| OS | 専用Ubuntu 22.04/24.04、Linux amd64 |
| GPU | RTX 4090一枚、24GB。画面表示や別のCUDA処理との併用を避ける |
| RAM | 128GiB。ホストで120GiB以上、Kubernetes allocatableで112GiB以上を確認 |
| CPU・接続 | CPU推論補助とアプリ分の余裕、十分なCPU・GPU間帯域 |
| ストレージ | NVMe推奨。モデル・コンテナー・動画・バックアップ用に250GiB以上の空きを目安に確保 |
| GPU共有 | NVIDIA Device Pluginで`nvidia.com/gpu.shared`を3枠。VRAMの分割・隔離を保証する機能ではない |
| 推論設定 | `charts/videoq-inference/examples/rtx4090-gemma4-embeddinggemma.yaml` |
| アプリ設定 | `charts/videoq/examples/local-ai-gemma4.yaml` |

回答・スライド読み取りは`google/gemma-4-26B-A4B-it`、埋め込みは`google/embeddinggemma-2`（768次元）、
音声は`openai/whisper-large-v3-turbo`です。各モデルは配布ファイル内でrevisionを固定しています。
OpenRouterとAI Gatewayは使いません。初回のイメージ・モデル取得にはインターネット接続が必要です。

チャット用の設定はBF16、8192トークン、同時生成1件、CPUオフロード40GiB、GPUメモリ利用率0.66です。
チャットPodはRAMを80GiB要求し、上限104GiBです。埋め込みはGPU利用率0.07、Whisperは0.12です。
残りは他プロセスや実行時の余裕ですが、利用率の合計が1未満でもOOMしない保証にはなりません。
画像は最大16枚を受け付ける上限です。実際に使う画像枚数・解像度・文脈で検証してください。

## 1. ホストと署名付きリリースを準備する

新規導入は[空のサーバーからの手順](lab-first-install.md)と[Ansible/GitOps手順](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-gitops.md)に従います。
AnsibleはRAM条件も検査します。GPUドライバー、NVIDIA runtime、K3s、Argo CD、内部Gitを準備し、
ノードに`videoq.io/inference-target=rtx4090`を設定します。80GB GPU用の`videoq.io/gemma4-vram`ラベルは使いません。
旧シェル/Textualインストーラーは廃止済みです。

ホスト上で、対象リリースのソースから読み取り専用の検査を実行します。

```sh
python3 scripts/gpu/rtx4090-preflight.py
```

RAM不足なら設定を小さく見せて回避せず、RAMを増設するか別の構成を選びます。
`gpu.shared=3`は物理GPUが三枚になったことを意味しません。

この新プロファイルを含む成功済み署名付きOn-prem Releaseを取得・検証します。
古い公開リリースには設定や`cpuOffloadGb`のチャート対応がありません。
ソースと配布物を混ぜたり、検証を省略したりしないでください。

## 2. 配置設定を生成して確認する

[GitOps手順の構成生成コマンド](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-gitops.md#1-検証済みリリースから構成変更を作る)を使います。
`scripts/gitops/promote.py`は新しい4090用Gemmaプロファイルとアプリ設定を選択します。
チャット用PVCは`videoq-gemma4-4090`、70GiBです。旧GPT-OSS用PVCは流用・削除しません。
署名付きイメージを内部レジストリへ保存し、生成差分を内部Gitで確認してからArgo CDで同期します。

既存クラスタでHelmを直接管理している場合は、署名検証済みチャートとイメージ設定を使い、
次の順序で適用します。Argo管理のリソースにはHelmを重ねて適用しないでください。
`/secure/inference-site.yaml`には少なくとも`fullnameOverride: videoq-inference`を指定します。

```sh
helm upgrade --install inference /secure/videoq-release/videoq-inference-VERSION.tgz \
  -n videoq --create-namespace \
  -f charts/videoq-inference/examples/rtx4090-gemma4-embeddinggemma.yaml \
  -f /secure/inference-site.yaml \
  -f /secure/videoq-release/verified-inference.json --wait --timeout 60m

helm upgrade --install videoq /secure/videoq-release/videoq-VERSION.tgz \
  -n videoq -f /secure/site.yaml \
  -f charts/videoq/examples/local-ai-gemma4.yaml \
  -f /secure/videoq-release/verified-images.json --wait --timeout 30m
```

`VERSION`は検証した配布物の実ファイル名に置き換えます。アプリのサイト設定にはDB・ストレージ・キュー・
Secret・公開URLを設定し、推論のサイト設定でGPU数・メモリ・モデルを上書きしないでください。
共有Device Plugin設定は`charts/videoq-inference/examples/rtx4090-device-plugin.yaml`です。
既存の[GPU準備手順](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-gitops.md)に従い、先に3共有枠を用意します。

## 3. 既存環境を切り替える場合

自動更新timerを止め、書き込みを停止してDB・ストレージ・キュー・鍵をホスト外へバックアップします。
モデル選択とホストRAM条件が変わるため、通常のアプリ自動更新として無人で切り替えません。
既存の更新journalを消して初期化し直す方法も使いません。[保守・復旧手順](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-auto-update.md)に従い、
新しいコンパイラーと生成差分を確認し、手動の保守作業として扱います。

```sh
sudo systemctl stop videoq-update.timer
```

旧GPT-OSS構成ですでに同じEmbeddingGemma 2のrevision・768次元・前処理を使っているなら、
チャットモデルだけの変更による再索引は不要です。Qwenや1536次元の埋め込みから移す場合、
またはrevision・前処理が異なる場合は、[埋め込み移行手順](local-inference.md)で全件を再索引します。
新旧ベクトルを混ぜないでください。旧モデルPVCと復旧用設定は、受け入れ完了まで保持します。

## 4. 実機で受け入れる

PodのReadyだけでは合格にしません。まずホスト上で次を実行し、三つのエンジンが同じ物理GPUを使っていることを確認します。

```sh
python3 scripts/gpu/rtx4090-preflight.py --node YOUR_NODE_NAME
kubectl -n videoq logs deployment/videoq-inference-chat --tail=100
nvidia-smi
```

チャットの起動引数が`--cpu-offload-gb 40`で、Gemma 4の固定revisionを読み込んでいることを確認します。
ログや共有資料へSecret・JWT・動画本文を貼らないでください。
その後、[実モデル・画面受け入れ](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-gitops.md)を使い、少なくとも以下を試します。

1. 日本語の短い動画をアップロードし、文字起こし・768次元の索引作成まで完了する。
2. 検索ツール、JSON形式の回答、ストリーミング、引用時刻からの再生を確認する。
3. スライドのタイトル・数式を読み取る質問を試し、画像機能が有効であることを確認する。
4. 音声・埋め込み処理と回答生成が重なる条件で、VRAM・RAM・応答時間・タイムアウトを測る。
5. Pod再起動と4領域の復元後に同じ動画で再試験する。

OOM、起動失敗、回答のタイムアウトが残る場合、この設定を動作確認済みとして公開しません。
同時実行を増やしたりGPU利用率だけを上げたりせず、失敗ログとピーク使用量から再調整します。
実機受け入れと復旧確認が済んでから、[自動更新の手順](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-auto-update.md)に戻ります。
