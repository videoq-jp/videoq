# Moodle・Google Classroom連携の確認状況

確認日: 2026-11-13。現在の実装、実環境で確認した範囲、未確認事項をレビューするための記録。

## 実装と反映済みの変更

- [VideoQ #1425](https://github.com/videoq-jp/videoq/pull/1425): 管理者が学校との通信を許可し、先生が自分のVideoQアカウントと所有講座を接続する方式。
- [Moodle #28](https://github.com/videoq-jp/videoq-moodle/pull/28): 導入するプラグインをlocal_videoqの1つに統一。実環境は0.25.4。
- [VideoQ #1430](https://github.com/videoq-jp/videoq/pull/1430): Moodleリクエストの登録・教材・権限取得にかかる処理を削減し、本番へ反映。利用者をまたぐ権限キャッシュは追加していない。
- [Moodle #29](https://github.com/videoq-jp/videoq-moodle/pull/29): 導入手順、先生・生徒向けガイド、受講権限変更と連携解除の回帰テスト。mainへ反映済み。

## Moodle実環境

対象はMoodle 5.1.8+／Boost、VideoQ講座9「【藤吉】ロボットビジョン」（16動画）。検証専用の先生・生徒セッションと一時講座を用い、既存の授業用連携を維持した。

| 確認項目 | 結果 |
| --- | --- |
| 先生のアカウント確認・所有講座選択・接続 | 通常の画面操作で成功 |
| 生徒の教材一覧・動画再生・動画切替 | 成功 |
| 生徒A/Bの保存済み質問・回答の復元 | 本人分を復元し、相手の専用ラベルの混入なし |
| 他人の実在する会話IDで取得・エクスポート | 双方向404 |
| 他人の会話IDで削除 | 所有者の会話が操作前後とも取得でき、内容も一致。削除APIの200だけで削除成功と判定していない |
| 先生の質問履歴・CSV | 通常画面から保存。9列・238行で列数が一致し、検証用生徒の質問と名前・メールが対応 |
| 生徒による先生用CSV・教材管理 | 403で拒否 |
| 同じログイン中の受講停止・受講解除 | Moodle coreの認可エラーで教材・履歴・会話一覧を拒否 |
| 受講再開 | 同じセッションで閲覧が復旧し、先生用操作は引き続き拒否 |
| 検証講座だけ連携解除 | 以後の教材・履歴・会話一覧は403。既存授業の教材・履歴は引き続き200 |
| CPU上限による503の比較 | 同じ教材一覧・履歴取得12回で、修正前6回から修正後0回 |

最終確認では保存済みの質問・回答を使用し、新しいAI生成・動画処理や有料プラン変更を行っていない。検証用講座を削除し、検証用生徒を停止、ログインセッションを無効化した。CSV・認証情報・質問本文を含む詳細な証跡は非公開で保持し、このリポジトリには含めない。

## 自動検証

CPU対策の関連テスト70件、API全体2104件（全体実行と依存導入後の対象ファイル再実行の合算）、Workersテスト58件、型検査、および本番反映前のCIが通過した。

Moodle #29ではオフラインのPHP契約テストに、同一利用者の受講停止・解除・再開、CSV権限取り消し、連携解除後の拒否を保持して再試行・セッション置換しないことを追加した。既存CIのPHP・ブラウザー検査、PostgreSQL・MySQLの導入・更新・削除検査が通過した。制御された権限状態を使う契約テストと、上記の実環境確認は区別する。

## 未確認事項と次の作業

- Google ClassroomはGoogle Cloudの本人確認が保留中。Educationテスト環境の申請承認は確認できておらず、実際の教師・生徒アカウントでの検証は未完了。プレビュー表示を実環境検証の代わりにはしない。
- Moodleは少人数・短い会話での確認。任意の同時利用数や長い履歴でCPU上限に達しないことまでは保証しない。
- 解除後に検証したのは、新しいMoodle経由のアクセスが拒否されること。発行済みメディアURLやダウンロード済みデータの回収は検証対象外。
- 次の利用者確認は、少人数の試験授業で操作上の迷いを確認する。AI質問を送信する場合は既存サービスの利用枠を消費する。
