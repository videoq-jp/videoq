# LTI 1.3 で LMS と連携する

VideoQ は LTI 1.3 による受講者の認証と、講座の教材を対象にした AI 回答を担当します。
Moodle は履修登録、元の動画ファイル、動画再生を担当します。2つの Moodle プラグイン、
配布 ZIP、導入手順、検証環境は別の
[videoq-moodle](https://github.com/yukiharada1228/videoq-moodle) で管理します。
通常の VideoQ ビルドにこのリポジトリは不要です。

## Moodle を接続する

1. 通常のデプロイ・DB 移行の手順で VideoQ を更新します。既存の公開 HTTPS URL
   `BETTER_AUTH_URL`、アプリ共通の `USER_SECRET_ENCRYPTION_KEY`、S3 互換ストレージの設定を自動利用します。
   `LTI_CONFIG` や `LTI_TOOL_KEYS` を別途登録する作業は不要です。
2. [Moodle の導入手順](https://github.com/yukiharada1228/videoq-moodle/blob/main/docs/setup.md)に従い、両方のプラグインを入れます。
3. 所有者の VideoQ アカウントの**設定 → Moodle と接続**で Moodle の正確な HTTPS ベース URL を入力します。
   発行した `VIDEOQ2.` コードを10分以内に Moodle の **VideoQ に接続**画面に貼り付けます。
   接続専用の同期 API キーや、動画ごとの JSON は不要です。
4. Moodle のファイル活動で **VideoQ の質問機能**を有効にします。Moodle cron と VideoQ の worker・queue・保守スケジューラを動かし、転送・文字起こし・検索準備の完了を待ちます。
5. 受講者として回答の逐次表示、引用、動画切り替え、Good/Bad の切り替え・解除を確認します。
   履修していない利用者から教材を利用できないこと、自分の試験教材の差し替え・削除が反映され、無関係な動画や個人の質問履歴が保たれることも確認します。

VideoQ サーバーから Moodle の HTTPS エンドポイントへ到達できる必要があります。
SSH のポート転送だけでは、ローカルの試用 Moodle を外部の VideoQ から利用できるようにはなりません。

## 署名鍵の自動管理

ログイン済みの所有者が初めて接続コードを発行するとき、VideoQ が RSA 署名鍵を自動生成します。
秘密鍵は既存のアプリ用暗号化キーで暗号化し、`lti_tool_keys` に保存します。
複数サーバーから同時に操作されても、所有者のトランザクション内のロックで初期化を直列化し、同じ鍵を共有します。
匿名アクセスや設定画面を開くだけの操作では生成しません。
初期化後は `GET /api/lti/jwks` から公開部分だけを取得できます。初期化前は空の鍵一覧を返します。

再起動や通常の更新で鍵は変わりません。DB バックアップには暗号化済みの鍵も含まれます。
復元時は、同じアプリ用暗号化キーを使用してください。保存済みの鍵を読み出せない場合は、
勝手に別の鍵へ置き換えずエラーにします。アプリの暗号化キーは既存のシークレットと共に保管し、通常の更新で作り直さないでください。

`0046_lti_materials` と `0047_lti_managed_keys` は、`0045_course_qa` までの通常の `main` に連携用テーブルだけを追加します。
既存の動画・講座・利用者のデータは変更しません。未公開の試用環境とは移行履歴が異なるため、
これらを試用 DB のアップグレード手順として実行しないでください。

## 役割分担と運用者向けの上書き設定

元の動画は Moodle が保存・再生し、処理用コピーは VideoQ が保存します。
質問ごとに Moodle の現在の権限を確認します。教材同期そのものは LTI 標準の機能ではありません。
LTI の認証を使い、教材の転送・照合は VideoQ/Moodle 間の独自サービス契約で実現します。

所有者は VideoQ の設定から接続を解除できます。以後の起動・質問・同期を拒否し、既存の学習データは保持します。
Moodle 側の信頼設定も無効にする場合は、Moodle 標準の外部ツール管理から VideoQ を無効化・削除します。
応答の失敗や欠落を、すべての動画を削除する指示として扱うことはありません。

管理者は `LTI_CONFIG=false` で自動設定を無効にできます。`LTI_CONFIG` の明示的な JSON 登録や、
運用者が用意する `LTI_TOOL_KEYS` は高度な用途向けの上書き設定として残し、既存値を優先します。
通常の導入では不要です。`generate-lti-tool-keys.mjs` も運用者が独自管理する場合の補助スクリプトです。
同じ issuer/client を静的設定と DB の両方に登録しないでください。

HTTP のみの開発環境では自動 LTI を有効にしません。Deep Linking、成績返却、名簿同期は対象外です。
LTI 認証取得や全 LMS との互換性を意味するものではありません。

本番で利用する Moodle・テーマ・ブラウザで確認してください。
[試用環境の検証記録](https://github.com/yukiharada1228/videoq-moodle/blob/v0.10.1/docs/integration-review.md)では、
別サイトでのチャット起動、100人分の動画全編配信、AI 回答の途中終了が未解決です。
手動設定の省略だけで、これらの解消や本番の処理能力・回答速度を保証するものではありません。
