# RTX 4090 1枚の研究室サーバー

専用のUbuntu22.04/24.04 amd64ホストと、24GBのRTX4090を1枚使う。
Ansibleがホスト・K3s・Argo CDを準備し、研究室内のForgejo/GitLabが設定を保存する。
ホスト内の更新サービスが、署名を検証した成功済み正式リリースへArgo CD経由で自動追従する。
GitサーバーとArgo CDの管理画面をインターネットへ公開する必要はない。

[研究室向けの導入手順](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-gitops.md)と
[自動更新手順](https://github.com/videoq-jp/videoq/blob/main/docs/guides/lab-auto-update.md)を使う。
SSH・LAN設定、Git接続キー、初回管理者の作成、内部CAの信頼、バックアップ、初回受け入れ、
アプリの自動更新を記載している。

GPUではGPT-OSS20B、EmbeddingGemma2（テキスト専用768次元）、Whisper large-v3-turboを
別Deploymentで同居させる。上流vLLMイメージをdigestで固定し、音声追加依存は別領域へ配置する。
自前の推論エンジンイメージはビルドしない。

[アプリ・復元の検証記録](https://github.com/videoq-jp/videoq/blob/main/docs/verification/rtx4090-production-acceptance-2026-11-12.json)には、
実モデル、画面からのアップロード・引用再生、4領域のcold restoreを記載している。
この記録だけで、後から追加した自動更新サービスの実機一貫検証まで完了したとは扱わない。
自動更新の受け入れ範囲は専用手順で確認する。

旧RTX4090専用のシェル/TextualインストーラーとRunpod向け予備プローブは廃止した。
研究室の新規導入はAnsible/GitOpsへ統一する。汎用単一サーバー導入とCPU開発向けツールは別経路として残す。

レンタルGPUは実機試験の間だけ起動し、実装・CI待ちと試験後は停止する。
停止後もディスク保持料金は別途発生する。
